# ProgramGrader 需求與設計文件

日期：2026-10-31

## 1. 目的

老師／助教要批改一批學生交的 Python 程式作業。手動逐份執行、比對輸出、再依評分標準給分、最後整理成績很耗時。

ProgramGrader 是一個 Django 網站：
1. 讓使用者**制定一份考卷的評分標準**（題目、配分、測資、時間限制、人工評分項目）。
2. **上傳整個資料夾**的學生程式碼，系統自動跑測資。
3. 提供**好用的人工評分介面**補上需要人判斷的部分。
4. **匯出 CSV 成績單**。

## 2. 目標 / 非目標 / 反目標

**目標**
- 一份考卷從設定 → 上傳 → 自動測資 → 人工評分 → 匯出 CSV 全流程可在網站內完成。
- 人工評分要「順手」：連續批改、鍵盤可操作、清楚看到程式碼與測資結果。

**非目標（這一版不做）**
- 登入／帳號／多使用者權限。
- AI 自動評分（之後可能接 Claude API，但這版純人工）。
- Python 以外的語言。
- 部署到 AWS（之後才做；但不要做出阻礙部署的設計）。

**反目標（做了等於失敗）**
- 匯出的分數和介面上看到的不一致。
- 重新上傳／重跑測資後，已填的人工分數被清掉。
- 學生程式卡死（無窮迴圈）導致整個網站卡住。
- 檔名不符格式的檔案被默默忽略，讓學生少分而沒人發現。

## 3. 使用者流程

1. **建立考卷**：輸入考卷名稱（例如 `A`）。
2. **新增題目**：每題設定題號（`A01`）、配分、時間限制、測資若干組。
3. **（可選）調整人工評分項目**：預設四項，可改名稱、比例、說明。
4. **上傳資料夾**：選一個總資料夾（內含多個子資料夾、子資料夾內含多個 `.py`）。
5. 系統解析檔名、儲存檔案、**自動執行測資**，完成後進入總覽頁。
6. **總覽頁**看全班 × 全題的狀態，點進某題開始**連續批改**。
7. **匯出 CSV**。

## 4. 檔案與命名規則

- 上傳方式：瀏覽器選資料夾（`<input type="file" webkitdirectory multiple>`），一次送出所有檔案。
- 結構：總資料夾 / 多個子資料夾 / 多個 `.py`。**子資料夾名稱不參與判斷**，只看檔名。
- 檔名格式：`學號_題號.py`，例：`D1234567_A01.py`
  - 學號：`_` 前的字串（例 `D1234567`）。
  - 題號：`_` 後、`.py` 前（例 `A01`），需對應到該考卷已設定的題目。
- 非 `.py` 檔（`.DS_Store`、`__pycache__` 等）直接略過，不警告。
- `.py` 檔但**檔名不符格式**、或**題號不在此考卷中**：列在上傳結果頁的警告清單，不匯入。
- 同一學號同一題出現多個檔案：視為衝突，列入警告，**取最後讀到的一份**並註明（建造者可調整，但必須讓使用者看得到）。
- 學生名單＝上傳檔案中出現過的所有學號（沒有預先匯入名單的功能）。某學號缺某題 → 該題「未交」。

## 5. 評分規則

一題配分 `S` 分，分成兩半：

| 部分 | 測資全過 | 測資未全過（任一筆錯誤／超時／執行錯誤／語法錯誤） |
|---|---|---|
| 測資分 | `S × 1/2` | `S × 1/4` |
| 人工分（四項標準） | `0 ~ S × 1/2` | `0 ~ S × 1/2` |
| **該題最高** | `S` | `S × 3/4` |

- **未交**：該題 0 分，不需人工評分。
- 測資分由系統自動決定，不需人工輸入。
- 該題若**沒有設定任何測資**：（我的決定）視為「測資全過」給 `S × 1/2`，並在設定頁提示「此題沒有測資」。
- 人工分 = 各項分數加總，每項上限 = `S × 1/2 × 該項比例`。

**預設人工評分項目**（每份考卷可修改；比例加總必須 = 100%）：

| 項目 | 比例 | 說明 |
|---|---|---|
| 題目需求理解 | 30% | 是否理解題目要求，知道需要完成哪些功能 |
| 核心邏輯與觀念 | 30% | 計算公式、條件判斷、程式流程是否正確 |
| 功能實作與結果 | 25% | 是否完成指定功能，輸出是否符合預期 |
| 程式可執行性 | 15% | 是否存在語法錯誤、變數錯誤或其他執行問題 |

例：`S = 20`，人工總額 10 分 → 需求理解最高 3、核心邏輯最高 3、功能實作最高 2.5、可執行性最高 1.5。

**評分項目屬於考卷層級**（同一考卷所有題目共用同一套項目與比例）。

**分數精度**（我的決定）：所有分數用 `Decimal` 計算與儲存（小數點後 2 位）；人工分輸入最小單位 0.1；介面與 CSV 用**同一個函式**格式化（最多 2 位小數、去掉尾端 0），只在顯示時格式化、不在中間步驟捨入，確保介面與 CSV 一致。

**評分後修改設定**（我的決定）：
- 人工分存「原始分數」。修改配分 S 或項目比例後，若某筆已填分數超過新上限，該格狀態退回「✋ 待人工評分」並在批改頁標示「設定已變更，請複查」，不自動換算。
- 刪除題目／評分項目：連帶刪除對應的檔案與分數，刪除前跳確認視窗說明會刪掉幾筆資料。
- 新增評分項目：該考卷所有已完成的作答退回待改（缺新項目的分數）。
- 題號可改名，已匯入的檔案與分數跟著題目走（以 DB 主鍵關聯，不以題號字串關聯）。

## 6. 測資執行

- 每組測資：`輸入`（stdin 全文）、`預期輸出`（stdout 全文）。
- 執行：以子程序 `python <檔案>` 執行，stdin 餵入輸入，捕捉 stdout / stderr。
- 時間限制：每題可設定，**預設 5 秒**，每組測資各自計時。超時即終止程序。
- **忽略 `input()` 提示文字**：學生程式的 `input("請輸入數字：")` 提示不算進輸出。做法：用一個小包裝腳本執行學生程式，先把 `builtins.input` 換成「不印提示、只讀一行 stdin」的版本，再以 `runpy` 執行學生檔案。只比對 `print` 等真正寫到 stdout 的內容。
- 比對：忽略每行行尾空白、忽略結尾多餘空行，其餘需完全一致。
- 每組測資記錄：通過／失敗／超時／執行錯誤，以及實際輸出、stderr（截斷到合理長度）。
- 執行用的 Python 直譯器 = 跑網站的同一個（`sys.executable`）。
- 安全性：這版只在本機使用，只做時間限制與在暫存工作目錄中執行；**不做沙盒**。部署上網前必須補上隔離（記在 CLAUDE.md）。
- 測資執行不可阻塞到讓網站無回應過久：（交給建造者）可以同步執行並在上傳完成後顯示結果，前提是 50 位學生 × 5 題 × 數組測資在合理時間內完成；若太慢，改用背景執行緒並在總覽頁顯示進度。

**重新執行**：
- 同一考卷可再次上傳，採**合併**（我的決定）：同學號同題的檔案會被**覆蓋**並重跑測資，**人工分數保留**；這次沒出現的學號／題目維持原狀，不會被改成未交。
- 覆蓋後若程式碼內容有變，該格狀態退回「✋ 待人工評分」（已填分數保留為批改頁的預填值，但在重新儲存前不計入總分與 CSV），讓人複查；內容相同則維持原狀態。
- 修改某題的測資後，提供「重跑此題測資」按鈕；人工分數保留。
- 在設定頁修改某題的時間限制後，自動重跑該題測資。

## 7. 畫面

### 7.1 首頁（資料夾）
- 考卷放在「資料夾」裡（一層，不巢狀）；首頁列出資料夾，**預設摺疊**，展開後列出考卷並可在該資料夾新增考卷。
- 考卷名稱在同一資料夾內不可重複。
- 每頁左上角有「← 返回」回邏輯上一層（測資頁、刪除確認 → 設定；批改 → 總覽；其餘考卷頁 → 首頁並展開所屬資料夾）。

### 7.2 考卷設定頁
- 考卷名稱。
- 題目列表：題號、配分、時間限制、測資（可動態新增／刪除多組「輸入 / 預期輸出」文字框）。
- 人工評分項目：名稱、比例、說明（預設四項）。
- 題目、評分項目、測資都有「＋ 新增」按鈕可加空白列。
- 測資頁可一次上傳多個 `.in` / `.out` 檔：同名配成一組、依檔名自然排序、預設加在現有測資後面，可勾「先清除這題的舊測資」；缺另一半的檔案列出警告。
- **每個輸入框都要有填寫指引**（placeholder 或旁邊的說明文字），例如測資框說明「每行一個輸入值，就像在終端機輸入的內容」、比例欄說明「加總需為 100%」。

### 7.3 上傳頁 / 上傳結果
- 選資料夾上傳。
- 結果：匯入了幾位學生、幾份檔案；警告清單（檔名不符、題號不存在、重複檔案）。

### 7.4 總覽頁（以進度為主）
由上而下：
1. **進度區**：整體完成率與 已改 / 待改 / 需複查 / 未交 份數；每題一列（題號、進度、待改數、需複查數），點一下從該題第一份待改開始批改。
   - 「需複查」= 曾評過分（有人工分數）但因設定變更或重新上傳而退回待改；與從未改過的「待改」分開計算與標示。
2. **匯出區**：匯出 CSV 按鈕在進度旁；尚有待改或需複查時寫明「尚有 N 份待改、M 份需複查，匯出只含測資分」，仍可匯出；全部完成時顯示可以匯出。頂部導覽不再放匯出連結，確保匯出前看得到說明。
3. **學號搜尋**：輸入學號，捲到成績表中該列並標示。
4. **成績表**：列 = 學號，欄 = 各題 + 總分；表頭、學號欄、總分欄固定，容器內捲動。格子顯示分數與狀態圖示（已完成 / 待改 / 需複查 / 未交）。點某格 → 批改該學生；點題號 → 從該題第一位待改開始。

### 7.5 批改頁（樣板 A，依題連續批改）
- 頂部：考卷 › 題號（配分）、進度（已改 / 總數）。
- 左側邊欄三個分頁：
  - **學生**：該題所有學生清單與狀態，可點選跳轉。
  - **同題分數**：該題所有已改作答的總分與各評分項目細分，可依學號或分數排序，標示目前學生，點選跳轉重改。
  - **相似程式**：同題中與目前程式相似度最高的幾份（相似度 %、對方分數），超過門檻標「疑似抄襲」；可開啟並排比較頁。系統只提示，不自動扣分。
- 中：程式碼（含行號、等寬字體）；下方為每組測資結果，失敗的顯示「輸入 / 預期 / 實際 / stderr」；顯示自動得到的測資分。
- 右：四項人工評分輸入（顯示各項上限）、評語（選填）、「儲存並下一位」。
- 鍵盤：Enter 儲存並跳下一位待改學生（建造者可加其他快捷鍵）。
- 輸入超過上限要擋下並提示。
- 未交的學生在清單中顯示但跳過。

### 7.6 相似程式（抄襲檢查）
- 只在同一題內比較。比對前把程式轉成 token：忽略註解與空白，非關鍵字、非內建名稱的識別字一律視為同一個符號（改變數名也抓得到）。
- 相似度 = 兩份程式「每 6 個連續 token 一組」片段集合的 Dice 係數 × 100（共有片段比例）；調換行序也抓得到，且每對只需一次集合運算，數百份也能即時算完。
- 門檻預設 80%，在考卷設定可調整（每份考卷一個值）。
- token 太少的程式（例如只有一行 print）不標疑似抄襲，避免誤判。
- 有語法錯誤無法 tokenize 的程式，退回以去除註解後的空白切分比對。
- 只用標準函式庫；在批改頁開啟時即時計算。

## 8. CSV 匯出

- 欄位：`學號, <各題題號…>, 總分`（題號依設定順序）。
- 一列一位學生，依學號排序。
- 未交：0。
- 尚未人工評分的題目：輸出目前已得分數（即只有測資分），（我的決定）不另加標記欄，總覽頁已有提示。
- 編碼：UTF-8 with BOM（讓 Excel 正確開中文）。

評語不進 CSV（只有學號、各題分數、總分，依使用者需求）。

## 9. 技術選擇

- Python 3.14、Django 6.1（專案已存在於 `ProgramGrader/`，使用 `.venv`）。
- SQLite。
- 前端：Django template + 少量原生 JavaScript；不引入前端框架。
- 上傳的程式碼存在 `MEDIA_ROOT`，或直接存 DB 文字欄位（交給建造者）。
- 不需登入；不使用 Django admin 作為主要介面（可保留供除錯）。

## 10. 交給建造者決定

- 資料模型細節、URL 結構、app 名稱。
- 樣式與版面細節（以樣板 C + A 為準）。
- 測資執行同步或背景（見 §6 的條件）。
- 程式碼語法高亮與否。
